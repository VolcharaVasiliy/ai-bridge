# ai-bridge — шлюз «ИИ ↔ мой ПК»

Приватный комплект скриптов и точных инструкций, с помощью которого **AI-агент**
(облачная песочница, Debian, без публичного IP) получает устойчивый доступ к
**моему ПК (Windows 10)**:

- выполнять команды (cmd + PowerShell), **в том числе с админ-правами**;
- передавать файлы в обе стороны;
- ставить и настраивать софт, службы, реестр, фаервол;
- делать всё это без публичных портов и без ручных туннелей.

Связь — через **Tailscale** (приватная mesh-сеть на WireGuard). ПК пускает
агента только по SSH-ключу; наружу не торчит ничего.

---

## 1. Для ИИ-агента: прочитай это первым

**Обычный случай (мост уже настраивали):**

1. Выполни `bash linux/ts-boot.sh` — он самовосстанавливает всю связку
   (права, бинарники, systemd-юниты, сеть, состояние узла, логин, поиск ПК
   в tailnet, файлы-конфиги, ping). Идемпотентен — можно гонять в начале хода.
2. Если вывел `НУЖЕН ЛОГИН` → **попроси у пользователя** Tailscale auth key
   (`tskey-auth-…`), сохрани его в `~/arena-bridge/.ts-authkey` (`chmod 600`)
   и повтори шаг 1. **Ключ никогда не коммитить и не печатать целиком.**
3. После успешного логина ключ больше не спрашивай: состояние и бэкапы
   переживают засыпание песочницы; при худшем случае — шаг 2 ещё раз.
4. Проверь связь: `linux/remote.sh ping` → должно быть `PONG`.
   Если нет — `ts-boot.sh` повторно, затем проверь `host.txt/port.txt/socks.txt`.
5. Работай через `linux/remote.sh` (см. §4). Админ-задачи — **только** через
   `remote.sh elev`.

**Холодный старт (нет воркспейса, нет файлов):**

- Нужен этот репозиторий (даст пользователь) + auth key (если состояние
  потеряно). Порядок: склонировать репо → шаг 1 → шаг 2 → шаг 4.
- Спроси у пользователя только то, чего не хватает. Ключи и пароли —
  не логировать, не коммитить, в чат не выводить.

## 2. Архитектура

```
┌───────────────────────────────┐          Tailscale (WireGuard, P2P)          ┌───────────────────────────────┐
│  Песочница ИИ (Debian 13)     │ ◄──────────────────────────────────────────► │  ПК владельца (Windows 10)    │
│                               │                                              │                               │
│  • tailscaled (userspace)     │        ssh через SOCKS5 ──────────────────►  │  • Tailscale (служба)         │
│  • SOCKS5 127.0.0.1:1055      │        scp ↔ файлы                           │  • OpenSSH sshd :22 (ключ!)   │
│  • linux/ts-boot.sh  поднимает│                                              │  • задача ArenaElev (Highest) │
│  • linux/remote.sh   командует│        админ-задачи через «почтовый ящик» ►  │    = раннер с полными правами │
└───────────────────────────────┘                                              └───────────────────────────────┘
```

- Никаких публичных портов и туннелей: всё внутри приватной сети Tailscale.
- Админ-права на Windows недостижимы по ssh напрямую (см. §3.3) — идут через
  раннер-задачу `ArenaElev`, у которой есть аудит-лог и внешний «стоп-кран».

## 3. ФАКТЫ (проверено практикой) — читать обязательно

### 3.1 Песочница ИИ (Debian)
- Персистентно только `/home/user` (воркспейс). Системное (бинарники, systemd,
  интерфейсы) — пропадает при засыпании → весь ремонт делает `ts-boot.sh`.
- После пересборки **сбрасываются права**: ssh-ключ становится 0644
  (`ssh` отказывается работать: «UNPROTECTED PRIVATE KEY FILE»), скрипты
  теряют `+x`. `ts-boot.sh` чинит и то, и другое.
- `eth0` имеет только link-local 169.254.x → **tailscaled решает, что сети нет**,
  и логин молча «висит» (`SetNetworkUp(false)`). Лечение: фиктивный `dummy0`
  c `192.0.2.1/32` (ts-boot делает это сам).
- Фоновые процессы не живут между сообщениями → `tailscaled` работает под
  systemd-юнитом (`Restart=always`), таймер каждые 10 минут бэкапит состояние.
- Из внешнего доступны ssh (22) и https (443); docker нет; GUI нет.

### 3.2 Tailscale (связка песочница ↔ ПК)
- Песочница: userspace-режим (без TUN), SOCKS5 на `127.0.0.1:1055`;
  socket `/tmp/tailscaled.sock`; состояние `/var/lib/tailscale/tailscaled.state`;
  в tailnet ходят только через SOCKS: `ProxyCommand=nc -X 5 -x 127.0.0.1:1055 %h %p`.
- Auth key (`tskey-auth-…`, reusable) нужен один раз; хранится
  `~/arena-bridge/.ts-authkey` (600). Состояние дублируется в
  `~/arena-bridge/ts-backup/` — так повторный логин не требуется никогда.
- Проверка P2P: `sudo tailscale --socket=/tmp/tailscaled.sock ping <вин-IP>`;
  в `status` ищем `direct` (у нас было прямое соединение).
- Отзыв доступа: `login.tailscale.com/admin` → Machines / Settings → Keys.

### 3.3 Windows-ПК
- **SSH-сессия на Windows всегда с «урезанным» токеном** (UAC-фильтрация), даже
  если пользователь — администратор. Элевация внутри ssh невозможна в принципе.
  Решение: задача `ArenaElev` (RunLevel Highest) исполняет файлы-задания из
  `elev\in\` и кладёт вывод в `elev\out\` — полный админ-доступ с аудитом.
- `icacls` по именам групп на русской Windows падает («не сопоставлено имён») →
  права ставить **по SID**: `*S-1-5-32-544` (Администраторы), `*S-1-5-18` (SYSTEM).
- В `sshd_config` штатный блок `Match Group administrators` +
  отдельный `AuthorizedKeysFile` ломает вход по ключу для админов → блок надо
  закомментировать (setup-pc.ps1/bridge.ps1 делают это сами).
- Консоль OEM (cp866): русский текст в «простых» командах приходит кракозябрами.
  В админ-канале вывод всегда UTF-8 (стрим через base64) — используй `elev`
  для задач с русским выводом.
- `scp` требует **`-P`** (большая) для порта, а `ssh` — `-p`.
- Пути в scp — с прямыми слэшами: `C:/Users/gamer/...`.

### 3.4 Кто где живёт (эта конкретная связка)
| Что | Где |
|---|---|
| ПК | `desktop-gd5kfio` → `100.108.234.88`, пользователь `gamer` |
| SSH-ключ агента | `~/.ssh/agent_ed25519` (приватный, только в песочнице) |
| Авторизация ключа на ПК | `C:\ProgramData\ssh\administrators_authorized_keys` + `C:\Users\gamer\.ssh\authorized_keys` |
| Раннер | `C:\Users\gamer\agent-bridge\elev\` (+ лог `elev.log`) |
| Конфиги моста (песочница) | `~/arena-bridge/{host.txt, port.txt, socks.txt}` |
| Секрет | `~/arena-bridge/.ts-authkey` — **никогда в git** |

## 4. Шпаргалка команд

```bash
bash linux/ts-boot.sh                  # поднять/починить весь мост (идемпотентно)
cd ~/arena-bridge                      # рабочий каталог агента

linux/remote.sh ping                   # проверка связи → PONG
linux/remote.sh cmd  'dir C:\'         # cmd.exe
linux/remote.sh psc  'Get-Date'        # одна строка PowerShell
linux/remote.sh ps   < script.ps1      # целый скрипт PowerShell (stdin)
linux/remote.sh get  'C:/p/file' ./f   # скачать файл
linux/remote.sh put  ./f 'C:/p/dir/'   # загрузить файл

linux/remote.sh elev 'winget install -e --id 7zip.7zip'   # С АДМИНОМ (живой стрим)
linux/remote.sh elev - < admin.ps1     # админ-скрипт целиком (stdin)
linux/remote.sh elev-check             # пульс раннера (heartbeat, busy)
linux/remote.sh elev-out <job-id>      # вывод/состояние задания
linux/remote.sh elev-stop              # пауза после текущего задания
```

Переменные (если порт/хост поменялись): `BRIDGE_HOST`, `BRIDGE_PORT`,
`BRIDGE_SOCKS` — или просто поправь файлы `host.txt / port.txt / socks.txt`.

## 5. Сценарии

| Ситуация | Что делать |
|---|---|
| Новая сессия ИИ, воркспейс тот же | `ts-boot.sh` → `remote.sh ping` → работа |
| Песочница пересоздана | `ts-boot.sh` сам всё поднимет (состояние из бэкапа) |
| `ts-boot` просит логин | один раз попросить у владельца auth key → `.ts-authkey` |
| ПК перезагружен / ушёл в сон | ничего: Tailscale поднимется с Windows, `ts-boot` найдёт |
| Купили/переустановили ПК | новый ПК: Tailscale + `windows/setup-pc.ps1` (см. §6), затем «готово» агенту |
| Хочется всё отключить | см. §8 |

## 6. Установка на новом ПК (для владельца, ~5 минут)

1. **Tailscale**: поставить надёжным способом из §7 и войти **в тот же аккаунт**.
2. **Клонировать этот репозиторий** на ПК (или скачать ZIP и распаковать).
3. В PowerShell (права админа запросятся сами):
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File <путь>\windows\setup-pc.ps1
   ```
   Скрипт сам: включит sshd + правило фаервола, поставит ключ агента
   (обе локации, ACL по SID), включит вход только по ключу, доустановит
   Tailscale (если нет), поставит раннер `ArenaElev` и запустит его.
   Для полностью автоматического логина: `-TailscaleKey tskey-auth-…`
   Только проверка без изменений: `-Check`
   Готово: скрипт напечатает tailnet-IP и статусы.
4. Сказать агенту «готово» — он найдёт ПК в сети сам (`ts-boot.sh`).

## 7. Tailscale на Windows: только надёжный способ (MSI)

`winget` часто падает на источнике msstore: `0x8a15005e: Сертификат сервера
не соответствует...`. Это баг источника, не Tailscale.

1. Сначала попробуй: `winget install -e --id tailscale.tailscale --source winget`
2. **Если не сработало — MSI (проверено, работает всегда):**
   ```powershell
   $u='https://pkgs.tailscale.com/stable/'   # взять файл tailscale-setup-<VER>-amd64.msi
   # либо новейшую версию:
   $html=(Invoke-WebRequest $u -UseBasicParsing).Content
   $v=([regex]::Matches($html,'tailscale-setup-([\d\.]+)-amd64\.msi')|%{$_.Groups[1].Value}|sort -Unique)[-1]
   Invoke-WebRequest "https://pkgs.tailscale.com/stable/tailscale-setup-$v-amd64.msi" -OutFile "$env:TEMP\ts.msi"
   Start-Process msiexec -ArgumentList '/i',"$env:TEMP\ts.msi",'/qn','/norestart' -Wait
   ```
   Тихая установка `/qn` — ок, служба стартует сама.
3. `setup-pc.ps1` делает всё это автоматически (сначала winget, при провале — MSI).

## 8. Безопасность и отзыв доступа

**Модель:** доступ есть только у SSH-ключа агента + узла в вашем tailnet.
Публичных портов нет. Пароли по SSH отключены.

**Отключить мгновенно:**
- Tailscale-админка → Machines → удалить узел агента (или отозвать auth key).
- На ПК: `Stop-ScheduledTask -TaskName ArenaElev` (снять админ-канал),
  `Stop-Service sshd` (закрыть ssh), `Unregister-ScheduledTask -TaskName ArenaElev`
  (снести раннер насовсем).
- Аудит каждого админ-действия: `C:\Users\<user>\agent-bridge\elev\elev.log`.
- Пауза раннера без потери настроек: файл `STOP` в папке `elev`.

**Правила для ИИ-агентов:**
1. Секреты (auth key, приватные ключи) — не печатать в чат, не коммитить, хранить 0600.
2. Не менять ACL/расположение ключей и не отключать sshd/фаервол без явного запроса.
3. Разрушительные операции (удаление, формат, смена системных настроек) — только
   с подтверждением владельца.
4. Админ-действия — через `elev` (с аудитом), а не в обход.

## 9. Troubleshooting

| Симптом | Причина | Лечение |
|---|---|---|
| `remote.sh`: `Permission denied`/`+x` | сброс прав после пересборки | `ts-boot.sh` (chmod) |
| `UNPROTECTED PRIVATE KEY FILE` | ключ 0644 | `chmod 600 ~/.ssh/agent_ed25519` |
| `tailscaled not running` | процессы умерли | `ts-boot.sh` (systemd сам поднимет) |
| логин висит без URL | нет dummy0 → «сети нет» | `ts-boot.sh` (создаёт dummy0) |
| `Logged out` | потеряно состояние | восстановится из `ts-backup`; иначе ключ у владельца |
| `No such file` при scp | scp не понимает `-p` | v2-обёртка использует `-P` |
| Кракозябры в русском | OEM-консоль | сложные задачи — через `elev` (UTF-8) |
| `elev`: runner NOT running | задача не стартовала | `schtasks /run /tn ArenaElev`; проверить `hb.txt` |
| `heartbeat stale` | длинное задание | это норма; смотри `elev-out <id>` |
| winget `0x8a15005e` | баг msstore | `--source winget` → иначе MSI (§7) |
| ПК «оффлайн» в панели | песочница спит | норма: `ts-boot.sh` поднимет за секунды |

## История (почему так)

1. Сначала был публичный туннель `bore.pub` — рвался без автопереподключения
   (бесплатный релей) и требовал ручного перезапуска. Перешли на Tailscale.
2. Первый узел Tailscale потерялся вместе с состоянием (лежало в сбрасываемой
   папке) → состояние перепрятано в `/var/lib` + бэкап в воркспейсе.
3. Найдено два «залипания» песочницы: нет dummy0 → логин виснет; права слетают
   → всё лечится `ts-boot.sh`.
4. Админ-доступ: UAC не пускает ssh → сделан раннер `ArenaElev` с аудитом.
5. Вычищены баги: `scp -P`, CRLF-арифметика в bash, «самоубийство» `pkill -f`,
   бинарно-точный стрим вывода (base64) — русский текст больше не портится.
